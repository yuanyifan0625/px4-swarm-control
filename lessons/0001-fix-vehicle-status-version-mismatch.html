修正 VehicleStatus 版本不相容

目標：看見 AttributeError 時，能快速判斷是 message contract 問題，並把修正留在 PX4 adapter seam。

錯在哪裡 怎麼修 怎麼驗證 速查表
30 秒結論

程式是按新版 VehicleStatus 寫的，但 runtime 載入的是 v1.17 message。v1 沒有該欄位，所以直接存取必然拋錯。修正在 adapter 做安全欄位轉換，topic 名則依每個 message 的版本產生；上層完全不動。

1. 錯誤不是飛控失效，是 contract 不一致

offboard_available = vehicle_status.accepts_offboard_setpoints
# AttributeError: VehicleStatus 沒有這個欄位

目前正式組合是 PX4 firmware d6f12ad 與 px4_msgs 86d8239。兩邊的 VehicleStatus 都是 v1，具有 pre_flight_checks_pass，但沒有 accepts_offboard_setpoints。因此錯誤是確定性的，不是偶發 race condition。

PX4 VehicleStatus v1 ↓ raw px4_msgs Px4VehicleInterface adapter ← 相容修正放這裡 ↓ internal VehicleState vehicle_node → /MAVN/status → ground station

如果在每個上層 caller 都加 hasattr，版本知識會擴散；未來改版要改很多處。Adapter 已經負責把 raw PX4 telemetry 轉成 internal model，所以它是正確 seam。

2. 解法包含兩個彼此獨立的修正

A. 欄位 shape：缺少時保守映射

def current_mode_accepts_offboard_setpoints(status) -> bool:
    return bool(getattr(status, "accepts_offboard_setpoints", False))
  • v1 沒欄位：回傳 False，不再拋錯。
  • 較新版有欄位：保留 PX4 明確回報的值。
  • 不使用 nav_state == OFFBOARD 猜測，因為「目前模式」與「明確接受 setpoint」不是同一個事實。
False 的精確意思

它表示「沒有得到 PX4 的明確肯定」。在 v1 中也包含「這個版本根本無法回報」。它不表示飛機一定不能進入 Offboard。

B. Topic name：由 message version 決定

def versioned_topic(base, message_type):
    version = int(getattr(message_type, "MESSAGE_VERSION", 0))
    return base if version == 0 else f"{base}_v{version}"
MessageVersion結果
VehicleLocalPosition1vehicle_local_position_v1
VehicleStatus1vehicle_status_v1
VehicleCommandAck0vehicle_command_ack

這也修正了另一個隱藏問題：原本 command acknowledgement 被錯寫成 _v1。具名的 PX4_V117 profile 保存正式 revisions 與預期 message types，但不再複製一份容易過期的 suffix tuple。

3. 三層證據才叫修好

  1. Unit test：餵入沒有該欄位的 v1-shaped status，conversion 成功且得到 False；再測有欄位且為 True 的 shape。
  2. Compatibility smoke：確認 commits、八個 message definitions、版本、欄位與推導出的 topic names。
  3. Gazebo runtime：用 verbose endpoint inspection 證明三台都有 bare-DDS publisher，再完成起飛、移動、變陣、降落，logs 中沒有 AttributeError。

只看到 topic 名存在不夠，因為 subscriber 自己也會讓 topic 出現在 ROS graph。必須看 Publisher count 與 endpoint。

問題 1：為什麼不能在 ground station 補 hasattr？

查看答案

因為 raw PX4 shape 應被 adapter 隔離；放上層會擴散版本知識。

問題 2：缺少欄位時，為什麼不用 nav_state 推導？

查看答案

因為兩者是不同事實；推導會把未知誤報為已明確確認。

問題 3：為什麼 topic list 不是 runtime 證據？

查看答案

因為只有 subscriber 也會建立名稱；必須確認真正 publisher endpoint。
